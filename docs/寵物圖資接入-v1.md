## 接入規則

- 正式介面仍只信 `GET /api/pet-assets`，不讀本地清單作失敗備援，也不以名稱／物種猜圖。舊寵物缺 asset_key 或圖片失效，仍使用實際保存的 emoji。
- 領養圖庫、小夥伴清單、照顧詳情都按同一 asset_key 配圖。普通領養只送原規格的 `{name,asset_key}`；許願由管理員選擇已登錄的圖資並人工確認到家。
- 圖庫縮圖 lazy＋async，大圖 eager；固定尺寸防止載入時跳動。插畫解除原 emoji 圓形裁切，保留完整耳朵、尾巴、翼與觸手。顏色與原紫色彈窗版型不變。
- 本地 `scripts/pet-preview/` 使用發布清單的已驗收圖，領養、準備、到家只操作合成記憶體資料。收據以使用者＋操作種類＋request ID 區分；`by-request` 只查 create，arrival 重送原 key 取得收據。

## 檢查

- `frontend/scripts/pet-assets-check.mjs` 是唯讀發布閘門：檢查 28 個不重複 key／URL、真 RGBA alpha、透明背景與不透明主體、四邊透明、384px 網站尺寸與單檔大小；不以「看見棋盤格」代替檔案檢查。
- `frontend/scripts/pet-assets.test.mjs` 驗證 PNG 的五種 scanline filter，以及拒絕 RGB 假透明、全不透明、空白與觸邊圖。
- 視覺 QA 是原稿／深紫／淺色／棋盤格素材檢查，不是瀏覽器或實體 Safari 驗收。沒有在正式站試領養、照顧或到家。

## 實測結果

- 28／28 網站圖資通過獨立 PNG 解碼驗證，384×384 RGBA，每張有透明背景、不透明主體、四邊透明。總計 4,136,329 bytes，相較 50,828,483 bytes 的高解析透明原稿縮減 91.86%；28 份白底原圖與 masters 的 SHA 均未改。
- 原稿只去除與外側相連的近白背景，渡鴉、蝴蝶、蜜蜂的少數封閉背景縫隙使用個別檢查過的種子點。眼睛高光、淺色毛髮、輪廓內的白色筆觸保留；只在邊緣三像素範圍作去白邊估算，不重畫身體。
- 主整合任務檢視兩批紫底／淺底總表、貓與兔子放大圖、兩批 128px 網站縮圖；圖資子任務另完成逐張近照、棋盤格與解剖／縫隙檢查。沒有把素材 QA 宣稱為瀏覽器或實機 Safari 驗收。
- [完整來源、SHA 與逐張驗證](pet-assets-v1-provenance.json) 留在版本庫，未放進公開圖片目錄。發布清單 SHA256：`1ceca794f8b6a9ae48907e82dc8dc084cf3acb5c20ea404d8cdefe7910a4e8a4`。
- 540 項本地非瀏覽器測試通過；正式 TypeScript、四個預覽入口 TypeScript、2393 條介面文案、修改檔 lint、production build 通過。既有 JS bundle 大小提醒仍在。
- 本地預覽 HTML／gateway 模組回 200；28 張圖片均回 `image/png`，HTTP 內容 SHA 與磁碟一致。PWA precache 仍為 20 個項目，沒有預先下載整批寵物圖。
- 獨立只讀複核發現 preview 原本未按 operation 隔開收據，已修正並補測試；複核確認沒有剩餘 P1／P2。
