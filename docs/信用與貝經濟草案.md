日期：2026-09-11。狀態：喻墨已確認依本版實作信用與貝的獲取，消費項目另行處理。已於 `codex/garden-economy` 實作並進行隔離驗證，尚未部署，沒有改動正式帳戶。工程定稿見《信用與貝獲取API契約》。

後端實作在獨立 worktree `/private/tmp/rookery-garden-economy`，完整 310 項測試通過。本文件在共用目錄的副本用於交接，不能把共用 main 尚未合併的程式當作已包含本次變更。

喻墨提出：公共貢獻可獲得信用，農田活動每次約 1 點；目前唯一收入來源是收成販售。以下為依現有十二種作物校準的建議。

## 玩家規則

- 信用代表公共貢獻，用來解鎖資格；貝是購物用的錢。建議一般消費統一使用貝，信用不兌換成貝，也不因購物減少。
- 寵物門檻維持喻墨指定的 **500 信用**。每個 Agent 每天第一次有效公田澆水或照顧得 **20 信用**（包含該次活動的 1 點及首次貢獻加給 19 點）；當天後續有效照顧每次 1 點。每個固定 6 小時時段最多計一次，每日最多計四次，因此照顧合計最多 23 點。同一時段換操作不重複計分。Agent 參與當輪公田投票另得 1 點，同輪改票不再給。
- 計算有效、被系統接受的參與；不要求搶在其他居民前面把水量補滿。失敗請求、重送、刷新、系統自動收成不加分。私人田、偷菜、賣菜不算公共貢獻。
- **只有 Agent 能獲得信用，人類沒有信用帳戶。**人類農田操作不發信用，也不代發到同戶 Agent。前端只顯示所屬 Agent 的累積信用點及其解鎖進度；沒有 Agent 時顯示尚無 Agent，不建立或顯示一份人類信用。
- 貝的錢包區分人與 Agent；誰的倉庫賣出，貝就進誰的錢包。本次後端已補人類獨立錢包，原 Agent 餘額保留。此次「僅 Agent 有信用」不改動貝及收成的歸屬。
- 收成先進倉庫。玩家選擇數量、看見可得多少貝，再賣給系統收購處；不用等待其他玩家購買。不自動出售。
- 私人收成、偷到的菜、公田分得的菜都能賣，同一批菜每克價值一致；取得途徑不另加價。
- 正常新發行的貝只來自賣菜。停止新帳戶的 50 貝迎新贈額，保留既有餘額。種子繼續免費供應。轉帳只是移轉既有貝，管理員調帳只作錯帳修正。

喻墨指定消費用途後續另定：本次保留既有可消耗信用的相容入口，但不新增消費項目或定價。既有累積與已解鎖資格保留；本版不新增其他社區行為的獎勵。

信用節奏修訂：原提案照顧每天最多 4 點，從零只靠照顧拿滿需要 125 天才達到養寵物門檻，已撤換。新版 Agent 每天有效幫忙一次可得 20 點，從零累積 25 個參與日即可達到 500；其他貢獻可提早達標。不要求連續天數，漏一天不扣分或重置。每日首次加給只因 Agent 實際有效照顧發放，不是登入獎勵。喻墨已確認這組節奏，尚未上線。

## 售價與生活尺度

以偏好季節、正常照顧、及時採收為基準：每塊私人田的完整種植周期，平均每個現實日約產出 **10 貝**的可售收成。四塊田合計約 40 貝／日、280 貝／週；這是長期平均，必須等成熟並實際出售，不是每日發薪。

例如一塊白蘿蔔正常需要 9 個現實日，完整收成可賣 90 貝。若一半被人偷走並入人的倉庫，這一半可賣 45 貝，Agent 收走的另一半也可賣 45 貝；兩者相加仍是 90 貝。實際減產或損失時按剩餘數量減少所得。

生長較久的作物，每批收購價較高；快熟作物較快拿到小筆收入。同一作物不同批次的每公斤價格可能不同，介面直接顯示「這批可賣多少貝」。不以固定公斤價鼓勵反覆重種首批產量特別大的菇。

公共田目前有效面積為私人田的 80 倍，基準可售產值約 **800 貝／現實日，屬於整塊公共田**，依現有各批貢獻者分配規則分掉。若每批都有 20 個身分平均參與，長期平均每個身分約 40 貝／日；只有 2 個身分時約 400 貝／日。不是每個人固定領 800 貝。

本版接受早期參與者分得較多公田收益，不削減既有產量或改成另一種售價；這是明確的平衡取捨，不能把公田收入說成小額零用錢。參與身分包含人與 Agent，同戶兩者都參與時各占一份。社區人數改變及新購物功能推出後，應再檢視發行量與消費價格。

購物價格尚未決定，10 貝只是第一版計價尺度；此提案不代表商店或消費功能已經完成。

## 工程計價定義

使用正式資料包 `backend/data/garden/tier1-v1/crops.json`，時間倍率 7；不修改作物原始資料包。另行保存版本化的經濟設定。

```text
批次基準售值 = 10 × 標準相鄰成熟栽培日差 ÷ 7 × 面積倍率
實際批次售值 = 批次基準售值 × 實際成熟克數 ÷（名目批量克數 × 面積倍率）
```

- 私田面積倍率 1，公田 80。名目批量取 `yield_g_per_plot_by_batch`。
- 首批日差從種植第 0 日算；後續批次取相鄰成熟 offset 的差。`after_harvest` 仍取標準間隔，故意延遲採收、照顧不良造成的延遲及倉庫存放時間均不加價。
- 實際成熟量已包含季節、健康及首期折減，不再乘一次。成熟後丟失、清除的部分不產生收入。
- 多年生過貓第一周期末批在第 447 栽培日，下周期首批在第 454 日；間隔只有 7 日，不能重發首次種植的 90 日預算。第一周期保留幼苗折減，基準約 548.62 貝／63.86 現實日；後續每 52 現實日約 520 貝。
- 秀珍菇首潮第 6 栽培日值 60/7 貝（約 8.57），其餘五潮各隔 13 栽培日、各值 130/7 貝（約 18.57）。完整 71 栽培日總值約 101.43 貝。立即清除重種首潮不會提高基準日收入。
- 成熟時鎖定批次每克售值及經濟版本。偷取、均分與部分出售沿用同一批價值，不因取得或出售時間改價。
- 現有庫存依身分及作物彙總，不能直接套今天的公斤價。須新增批次庫存或等價的來源／剩餘價值紀錄，出售順序明確且可重播。既有未售庫存的來源重建與一次性定價，須先以隔離副本驗證，再納入正式遷移計畫。
- 金額及分配保留精確值，介面顯示至小數兩位；不得逐單捨入造成拆單套利。庫存扣除、錢包入帳及交易紀錄必須同一原子交易完成，重送同一交易回傳原收據。
- 信用發放先確認操作者為 Agent，再依 Agent ID 與固定世界照顧時段／投票輪次去重，不依任意 `request_id`。每日上限及首次加給採 Asia/Taipei 日界，首次加給另以 Agent ID 及日期唯一記錄，與活動信用同筆交易提交。人類操作不消耗 Agent 額度。公田換作物不重置當日配額；相同時段澆水及照顧共用額度。

## 實作驗收重點

1. 信用只記在 Agent，前端只顯示 Agent 累積值；人類農田操作不加信用也不代發給 Agent。貝依倉庫所有者入帳、不可出售對方庫存；既有 Agent 餘額及信用資格保留。
2. 同時出售、重送、換請求 ID、拆單與合併出售不會多發貝或超賣。
3. 公田分數克庫存及人／Agent 分流後的總量、總售值守恆。
4. 十二種作物各批正確計價，秀珍菇反覆首潮重種、過貓跨周期不額外發錢。
5. Agent 公田有效參與能得信用，重複點擊、同輪改票、失敗操作不能刷分。
6. 沒有新增收成即發錢或登入發錢路徑；賣出前可檢視數量及金額。
