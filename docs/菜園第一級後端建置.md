## 最終本機驗收

2026-09-11 主 agent 執行 `python run_tests.py`，全套 **226 個測試通過，20.105 秒**：既有後端 136 個，加菜園 90 個。菜園包括引擎 19、服務／HTTP 與併發 41、REST／MCP／排程入口 24、獨立複核 4、migration 2。原有修復的測試仍全部通過。

全 12 種首周期共 164 批皆實際走完種植、照顧、生長、偷取、實收與持久庫存，並核對每批及全周期量；服務另驗過貓第二周期首批，引擎驗完整兩周期 104 批。真 SQLite 多連線競爭、寫入故障回滾、重試與重新建立連線後的資料保存皆通過。另以真 REST JWT 與 MCP Tool.run 跑原始秀珍菇資料首收，驗成熟前 1 µs 拒絕、成熟即能偷取、庫存及圖鑑不重複。

Migration 已驗舊表資料保留、重跑不重建遊戲，以及沒有 `.env`／JWT_SECRET 的獨立程序仍可只建七張菜園表。測試使用暫存 DB 和模擬伺服器時間，未等待現實數十天，也未使用正式住戶。全套唯一已知提醒為既有本地 Qdrant 的 payload index 提醒，不影響本輪通過結果。

## 實作範圍

- 四塊同戶私田：agent 種植、照顧、採收；user 澆水、偷取；雙方針對同一植株及提案同意清除。單次收根／整株作物依卡片的 `empty` 結束；仍活著的續採作物生產結束須共同清除，與病死分開。
- 全 12 種正式時程及每批產量；獨立成熟批不合併，採後再生必須等餘量實收，過貓延續多年周期及首期折減。成熟量鎖定，零收量關閉，不把等待不存在的收成變成永久卡住。
- 每批偷取一次 50%，立即入 user 倉庫，無保護期；餘量只在 agent 採收時入 agent 倉庫。兩個身分庫存分開保存，只有同戶私田正數 agent 實收才記錄圖鑑；12 種全齊顯示第二級解鎖，第二級作物資料與種植仍屬後續交付。
- 公田由系統種、收、分配及整輪結束清理投票。user 和 agent 是不同身分，不以同戶合併、不按照顧次數加權。同個六小時 tick 的分配快照跨交易保存；首次採收後的新照顧放入下一分配期。無貢獻者時記未分配損失。
- 公田每個身分每輪一票，截止為真實 12 小時；同票取最後有效伺服器序號，沒票使用可重現且保存結果的系統抽選；優先未種過作物，有限續採全部收完才換輪，多年生不強制周年挖除。
- 成熟、照顧、病蟲與跨月都用伺服器時計補算。網頁刷新不額外增加時間、重抽或自動採私田。六小時照顧與 24 小時損害寬限不影響立即偷取。

## 製作端定下的工程初版

種田任務確認正式 epoch 原本留待發布配置。`GardenWorld` 第一次建立時，保存伺服器 UTC 時刻與隨機種子；該時刻對應菜園 `2026-01-01T00:00:00Z`，之後沿 Gregorian 日曆以七倍前進，月份依實際月長。重啟或重新整理沿用資料庫的 epoch，不把原示範的 9 月 9 日當成正式起點。

公田既有總面積為一畝約 667 m²。v1 選 480 m² 為有效栽培面積、187 m² 保留通道與作業，有效值保存在 `GardenWorld.public_productive_area_m2`。相對每私田 6 m² 基準為 80 倍，只在成熟產量公式乘一次；不是把總面積當有效面積，亦不是把舊「整戶四地 20 倍」再乘每私田。菌菇也按實際配置等比換算，無額外玩家購買／設置步驟。

## 持久性與併發

新增七張 `garden_*` 表：共用世界、地塊聚合、操作回執、身分庫存、帳本、同戶圖鑑及操作／系統紀錄。每批的身分由伺服器種植 UUID、周期及批次組成。公田份額及累計庫存使用精確分子／分母文字儲存，API 的 `quantity_g` 為整數或分數字串，不把尾差分給特定身分。

目前正式架構使用 SQLite。每個操作在讀取地塊前取得 `BEGIN IMMEDIATE` 寫鎖，將批次、庫存、帳本、圖鑑與 idempotency 回執一起提交。不同 API、MCP、timer 程序共享資料庫鎖；四地批次請求則逐地分開交易。相同身分及 request_id 重試回原結果，不再次執行；同 key 改內容回 409。失敗操作不影響同份批次的其他地塊，寫入故障則整筆回滾，原 request_id 可安全重試。

查詢地塊會補算已經過的伺服器時間，因此仍會取得寫鎖並保存結果；倉庫／圖鑑查詢只讀持久結果。上線容量擴大後需觀察單 DB 寫入排隊情況；本輪驗證的是現有 SQLite 架構，未宣稱跨不同資料庫引擎的等價併發驗收。

## 發布前與回復

1. 依既有後端部署準備取得授權並備份正式 DB、程式、環境及 timer 狀態；仍需保留先前 migration 022 的登入撤銷語意。
2. 使用既有 Python 依賴即可，本輪沒有增加套件。對已備份的目標 DB 執行 `python migrations/023_garden_tier1.py <db>`；只建立七張表，可重跑，不先建立世界、播種或寫住戶資料。新環境由 API startup 的 metadata 建表。
3. 一起發布資料包、模型、服務、REST 與 MCP `garden` 工具；缺少任一作物資料或雜湊不符即拒絕載入，不降級成部分作物上線。
4. `garden_tick.py` 是獨立一次性工作；正式需另裝每分鐘執行的 timer，核對真正服務使用者／工作目錄／venv／設定。它只結算作物及公田，不啟動付費模型、不外發 webhook。頁內公田採收與投票通知保存在菜園 log，由查詢回應讀取；不是聲稱已接住戶站外推播。
5. 前端收到正式 schema 後，仍須完成 user 畫面接線與瀏覽器驗收，再安排全 12 種一起發布。不得從 main 的舊前端打包。這輪後端通過不等於正式環境或前端已完成驗收。

若需回復，先停止菜園 timer 與新菜園入口，再切回前一候選程式；保留所有 `garden_*` 表與帳本。已入倉的收成不因回復程式而刪除，不能把回復當成清資料。重新啟用會從持久 epoch／進度補算；長期停用是否凍結遊戲時間屬另一次產品決定，本輪不偷偷重設時鐘。
