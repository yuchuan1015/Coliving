# 鴉巢介面盤點

更新：2026-09-10。本輪修正「排程喚醒」。這是來源碼／路由盤點，不是 Safari 全站實機驗收。

## 怎麼數

目前 App.tsx 有 **36 條頁面路由**，不含萬用轉址，也不另計彈窗、FAB、表單分頁和同一動態路由下的多筆資料。艙室各家具共用 /home/:moduleId，所以不是「36 個功能」的意思。
分類：33 條主要畫面已接新版專用外框（含本輪排程），2 條主要画面仍舊版，1 條有載入畫面殘留。公共場域的青黑風與艙室的紫黑風是兩套已定稿表現，不把已批准青黑場域算成漏改。

## 確定的下一批（本輪只記錄，不擴改）

1. `/admin` 系統儀表板：一般／載入／非管理員狀態都還用舊工具類和 --bg／--ink 變數，沒有新版頁面外框。來源 AdminPage.tsx。
2. `/adopt` 領養室友：填寫表單仍舊；完成後的 AdoptionSuccess 有自己的新版區塊。來源 AdoptPage.tsx、components/AdoptionSuccess.tsx。
3. `/agent/advanced` 進階連線與房間設定：主要畫面已有 ya-agent-settings，未讀到室友時的載入畫面仍舊。只判斷外框，不把裡面所有控制項稱為已完成視覺驗收。

本輪 `/schedules` 改為 CabinUtilityShell，載入／失敗／空清單／有排程都在同一紫黑外框。頻率選擇、表单標籤、狀態、錯誤／重試同步；既有排程 endpoint 與參數不改。繁簡切換保留草稿、Cron 和居民文字不轉字。

## 後續維護

新增路由時同步這張表；回歸測試會比對 App.tsx 與表格，避免再新增一頁卻沒登記。外框已接不代表所有空狀態、錯誤狀態、彈窗都通過視覺驗收；那些需逐頁驗收時另記，不用「全站都好了」概括。

## 本輪排程驗證

- 保留 GET／POST /api/schedules、PATCH／DELETE /api/schedules/{id}。已閱讀最新 master 的契約：Cron 由後端按住戶時區計算，next_run 自带時區；前端不重算 Cron，顯示下次時間按帳號時區及選定語言格式化。
- 64字名稱／Cron、2000字訊息、512字Webhook上限與後端一致。名稱、訊息、Webhook不因翻譯改寫。
- 新增、啟停、刪除加重複送出防護；刪除需確認。失敗保留資料與草稿；載入失敗不假裝沒有排程。
- 本地預覽沿用 5186、page=schedules；只使用記憶體示範排程，不建立正式排程、不呼叫Webhook或喚醒室友。正常／空／失敗可用 schedule-state=empty 或 error切換。
- 驗證涵蓋繁簡、preset/custom payload、重複送出、錯誤保留、確認刪除、重試、卸載遲到回應、時區格式、作用域CSS與路由清單。
