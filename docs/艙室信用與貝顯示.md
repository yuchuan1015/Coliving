## 本輪範圍

- 艙室上卡保留登入頁一致的深紫黑玻璃風格，左側時間／天氣上下排；依使用者後續要求，右側改成小型星芒信用圖標／貝殼貝圖標＋數字兩行，16px 圖標、14px 數字，不顯示長標籤。公告仍在分隔線下方。
- 超過四位整數（10,000 起）顯示「萬」，最多一位小數，向下截取不誇大餘額：9,999 → 9,999；10,000 → 1萬；12,345 → 1.2萬；123,456.78 → 12.3萬。簡體顯示「万」。小額貝保留原兩位小數；完整數字保留在輔助閱讀標籤／title，不修改任何後端數值。
- 中間家具場景、底部 Agent 卡片、家具錨點與 FAB 不變。上卡使用內容最小高度，過長數值／失敗訊息可換行增高，不壓住公告。
- 寵物只核對現有功能並討論詳細彈窗方向，未修改 PetActions、餵食／健康規則或使用上一輪尚待去背的寵物插畫。
- 開發階段未 commit、push、部署；本次已取得發布授權。沒有呼叫正式帳號 API，也未修改後端或資料庫。

## 讀取契約

1. `GET /api/credit/summary` → `credit_total`，只讀 Agent 累積信用，不顯示 `consumable`，不依 action 的 `credit_awarded` 前端累加。
2. `GET /api/shell/summary` → Agent 錢包；新版保留 `shell_balance_display` 的两位小數字串，並保留 `shell_balance_exact` 作精確餘額說明。分數與大額不轉成浮點。不是 `garden/market?owner=user` 的人類錢包。
3. 尚未升級的舊後端只有安全非負整數 `shell_balance` 時，原樣顯示整數，不擅自補小數。新版欄位存在卻不合法時顯示讀取失敗，不降回截斷的整數。
4. 已確認兩個唯讀 summary 足以實作這次顯示，不要求新增 API。精確小數何時在正式站生效，取決於後端經濟版本另行發布。

## 狀態與安全

- 真實零值才顯示 0；讀取中顯示省略號，失敗顯示破折號與重試，不填入範例數字。
- 無室友使用引導；只有 `403/detail=需要先領養室友` 判成缺少 Agent，其他 403 保持錯誤。
- 兩個讀取獨立完成；貝故障不隱藏已取得的信用。請求 15 秒 timeout。
- 首次進入、Safari pageshow、視窗 focus、頁面變回可見時重新讀取；同一輪讀取合併，不輪詢。
- unmount 取消請求並移除監聽。HomePage 的 dashboard 與家具／天氣 snapshot 均綁定 userId，信用元件以 userId/agentId 為 key；身分變動先移除上一位的數字與天氣／相框，晚到回應不能寫回。
- 不在 localStorage/sessionStorage 保存餘額，沒有轉帳、扣點、出售、贈送等動作。
