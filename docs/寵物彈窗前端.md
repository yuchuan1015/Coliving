## 契約與保護

- `GET /api/pets` → `{pets, max_pets}`；這個既有 GET 會由後端懶結算並 commit，並非唯讀診斷。只在打開入口與手動更新時讀，不做背景輪詢、focus 或 pageshow 刷新。
- `POST /api/pets/adopt` 新前端只送 `{name,asset_key}`；`POST /api/pets/{encoded_id}/interact` 為 `null` body 與 `action` query。照顧成功直接更新完整 PetStatus；普通領養成功後重讀寵物與許願容量，不自行扣剩餘格數。
- 每個請求有 15 秒 timeout 與本地 `_expectedUserId` 設定，沿用既有 session guard；它不進 body／query／header，不代替後端權限。切換居民會重新掛載小夥伴面板，過時回應不會恢復舊資料。
- 同步 single-flight 鎖擋連點，操作中禁返回、切換、重新讀取和關閉；取消確認不送 POST。
- 目前後端沒有 request_id／冪等收據，前端不偽造安全重試。網路失敗、5xx、無法驗證的成功資料／錯誤 ID 皆視為結果未明，不能直接再送；先由使用者重新讀取狀態。領養結果未明時，更新會先退回清單展示已入住寵物，再由使用者決定是否重新進入領養，不能在原表單直接再送。即使讀取成功仍明說不能據此確認前一筆成功，不把 GET 當收據，不自動領養第二隻。
- 讀取失敗移除舊資料並保留更新按鈕，不顯示假 0。列表可能包含本輪結算後 `is_alive=false` 的一筆：不佔活寵名額、不可互動，只呈現目前無法互動，不新增死亡倒數或死因敘事。
