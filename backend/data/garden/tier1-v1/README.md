## 接線行為

- 私田由agent種、照顧、採收；user只澆水、偷菜及原有共同清除面板。user不得透過payload偽裝agent。
- 新成熟批生成穩定ID；每批可偷一次五成，立即進user倉庫，剩餘等agent採收。沒有保護期。
- after_harvest型的相鄰offset差，從前批餘量實收後計；independent型按植株有效生長時間各自成熟，新批不等待舊批。
- 產量在成熟時依健康、季節及首期係數鎖定。已成熟批不重新抽量；未領取部分在全株失敗時記損失，已入倉不扣回。
- 過貓後周期使用原offset加cycle_index×repeat_cycle_days；只首周期套幼苗折減，後周期不重加育苗，也不把周期結束判死。
- 有限生產期完成與病死分開；私田健康植株仍依原雙方同意清除。公田全輪結束才系統清理投票，多年生周年繼續養株。
- 公田採收按當批有付出的不同身分完全均分。同tick多批共用清空前貢獻集合，結算完再清；精度不可使某人多拿尾差。
- 12小時投票使用現實時鐘，作物用七倍有效生長時鐘；重新整理不能推進時間或重抽問題。

## 製作端選定的v1預設

全年可選種，非偏好月份的生長與潛在產量為0.85倍；不再增加季節解鎖流程。支架、遮陰與菌菇環境是種植時套用的基礎配置。第一級種苗每次由系統提供，避免失敗後無法重種。

照顧狀態每6個現實小時結算；正常照顧維持長勢，缺水、缺養分或病蟲害先影響生長，持續未處理24小時才扣健康。基礎病蟲／污染事件機率為每tick 1%，環境問題時加倍；這些均為遊戲平衡值，不是農藝實測，也不是偷菜保護時間。完整數字見rules.json。

本批公田若沒有照顧者，系統採收記為未分配損失，不憑空分給未付出的身分。收成用途與農貿市場留待原定後續階段。
